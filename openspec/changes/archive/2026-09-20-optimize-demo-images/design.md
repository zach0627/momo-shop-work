# Design

## Context

- 部署：GitHub Pages（靜態主機，CDN 快取 10 分鐘，不提供圖片縮放）。這個選擇與理由見 `docs/architecture.md` §9：只是 demo，越簡單越好。
- 量測（改之前）：首頁 157 張圖合計 6,842 KB。商品圖寬 320–1000px，顯示 128–225px（降價好貨最多 7.8 倍）；猜你想搜 1000px、顯示 186px（5.4 倍）；banner 類都在 2.5 倍以內。以 curl 量 GitHub Pages：未快取的檔案約 0.45 秒才開始傳。
- 素材進入網站只有一條路：`tools/import-assets.mjs`；商品資料由 `tools/gen-fixtures.mjs` 從素材產生。

## Goals / Non-Goals

**Goals:**

- 首頁下載的圖片量明顯下降。
- 在一般與 2 倍像素密度的螢幕上都不糊：圖的實際像素不少於顯示寬度的兩倍（原圖比較小時除外）。
- 做法可重複：重新匯入素材得到一模一樣的檔案。

**Non-Goals:** 見 proposal 的 Non-goals（正式環境的圖片方案、banner、模擬延遲、lazy loading）。

## Decisions

### 1. 在素材匯入時縮圖，檔案直接進版控

**選擇**：`tools/import-assets.mjs` 在複製素材時就產生縮好的檔案；縮好的圖和其他素材一樣 commit 進 `apps/shop/public/assets`。

**放棄的方案**：

- **build 時縮圖（Vite 的圖片 plugin）**：每次 build 都要縮一百多張圖，CI 變慢，還要多一層設定；素材很少變動，縮一次就夠。
- **圖片 CDN 即時縮圖**：GitHub Pages 沒有，要換主機，違反「越簡單越好」。
- **`srcset` 提供多種寬度**：卡片寬度是固定的，一種尺寸就能在 1x 與 2x 螢幕上都清楚；多種寬度要改元件、檔案數也翻倍。正式環境才需要。

### 2. 卡片圖的尺寸：這件商品出現過的最大卡片 × 2

**選擇**：工具知道每一區商品卡顯示多寬（實測：降價好貨 128、momo 店取與今日暢銷榜 140、限時搶購 208、你可能會喜歡 225），也看得到同一個商品 id 出現在哪幾區（每一區是一個素材資料夾），所以每件商品的卡片圖 = 它出現過的最大卡片 × 2。

**放棄的方案**：一律 480px（最大卡片 225 × 2 再取整）。實作過：商品圖只少了 60%，因為只顯示 128px 的降價好貨仍是 3.75 倍。改成依商品計算後少了 76%。

**為什麼要依商品而不是依資料夾**：有 4 件商品同時出現在兩區（限時搶購或今日暢銷榜，加上你可能會喜歡）。依資料夾的話，它們在 225px 的卡片上只有 1.2–2 倍。

### 3. 兩個版本放兩個欄位，資料形狀不變

**選擇**：卡片圖放在 `<資料夾>/card/<名稱>.webp`，詳情頁的圖放在 `<資料夾>/<名稱>.webp`。商品資料的 `imageUrl` 指向卡片圖、`images` 是詳情頁的圖；詳情頁改顯示 `images` 的第一張。

**放棄的方案**：新增 `thumbnailUrl` 欄位。`ProductCardItem` 本來就吃 `imageUrl`，而 `images` 本來就是「詳情頁的圖」；沿用既有欄位只要改欄位的說明，不用動介面。

### 4. 詳情頁的圖：已經夠小的 WebP 原檔照搬

**選擇**：原圖已經是 880px 以內的 WebP 就照搬，其餘縮到 880px 並轉成 WebP（品質 80）。

**理由與代價**：重新壓縮其實會再小一些（實測：momo 店取 318 → 198 KB、限時搶購 743 → 716 KB、你可能會喜歡 1,528 → 1,471 KB），但會多損失一次畫質。詳情頁一次只載入一張，選畫質。實作當下 Agent 曾把理由寫成「重新壓縮不會變小」，對照數字後更正（見 `docs/agent-workflow.md` §4）。

### 5. 只處理超過顯示尺寸很多的圖

**選擇**：商品圖全部處理；banner 類只處理猜你想搜（5.4 倍）。其餘 banner 在 2.5 倍以內，照原檔複製。

**代價**：banner 合計約 2.6 MB，現在是首頁最大的一塊。它們的顯示尺寸各不相同（同一個資料夾裡也不同），要處理就得逐張設定，這次不做。

### 6. 縮圖工具用 `sharp`

**選擇**：根目錄的開發依賴，只有匯入工具使用，不進任何 package、不進 bundle。它附預先編好的執行檔，不需要安裝腳本。

**放棄的方案**：ImageMagick（要另外安裝在每台機器上）、瀏覽器的 canvas（無法在腳本裡重現）。

## Risks / Trade-offs

- **各區卡片的顯示寬度寫在兩個地方**：匯入工具與驗證它的測試各有一份。卡片的版面改了，這兩份要一起改；UI 改了而這裡沒改，測試不會發現。
- **每次安裝多下載 `sharp` 的執行檔**（約 10 MB，CI 也會下載），即使只有匯入素材時才用得到。
- **卡片圖是有損壓縮**（WebP 品質 80）：在瀏覽器量過，每張已載入的卡片圖都是顯示寬度的 1.99–3.21 倍，沒有低於 1 倍的。
- **這是 demo 的優化**：正式環境仍需要依裝置提供多種尺寸的圖片服務。
